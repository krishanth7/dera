## 2. API Contract Inventory & Gap Analysis

| Layer / Capability | Phase 4.1 Baseline State | Phase 4.2 Target State | Evaluation / Gap |
|---|---|---|---|
| **Contract Schemas** | Ad-hoc Pydantic models in `schemas/health.py`, `schemas/system.py` | Centralized reusable contract architecture in `dera_api.contracts/` | Needs standard base models, envelopes, and metadata models |
| **Error Format** | Custom JSON wrapper `{"error": {"code": ..., "message": ...}}` | RFC 9457 Problem Details standard (`application/problem+json`) | Current schema lacks RFC 9457 compliance (`type`, `title`, `instance`, `status`) |
| **Error Taxonomy** | Informal string codes (`DOMAIN_FAIL`, `CONFIG_ERROR`) | Authoritative typed enum registry (`ErrorCode`) with documented remediation | Missing formal error registry and client retry semantics |
| **Validation Handling** | Custom handler returning raw FastAPI `exc.errors()` | Normalized `FieldErrorDetail` with standardized field paths and codes | Raw Pydantic error details leak framework internals |
| **Pagination Contracts** | None | Reusable `PaginationParams`, `PageInfo`, and `PaginatedResponse[T]` | Essential for future schema explorer & diagnostic queries |
| **Filtering & Sorting** | None | Typed `FilterCondition`, `FilterOperator`, `SortOrder`, and `SortParams` | Allowlist-only filtering preventing arbitrary SQL expression injection |
| **Identifier Validation** | None | Bounded slug, UUID, and database object identifier validators | Needed for safe URL path parsing |
| **OpenAPI Governance** | Runtime auto-generated by FastAPI | Version-controlled snapshot (`docs/api/openapi.v1.json`) with CI drift detection | Need repeatable export script and CI regression gate |
| **API Version Policy** | Static `/api/v1` mount | Documented backward compatibility and deprecation governance policy | Needed to govern future API evolution |

## 3. Strict Scope Exclusions

In accordance with project invariants and roadmap sequence:
- **No Phase 4.3 Database Persistence:** No platform database tables, SQLAlchemy models, or Alembic migrations.
- **No Phase 4.4 Authentication / RBAC:** No login, OAuth2, JWT tokens, or permission tables.
- **No Phase 4.5 Task Queues:** No Celery, Redis, or asynchronous worker pipelines.
- **No Phase 4.6 Telemetry:** No OpenTelemetry exporters or Prometheus collectors.
- **Zero AI / LLM Integrations:** Zero AI inference, models, embeddings, or agentic reasoning.

## 4. Phase 4.2 Implementation Architecture Plan

1. **Contracts Package (`apps/api/src/dera_api/contracts/`):**
   - `base.py`: `DeraBaseModel` with strict serialization rules (snake_case, UTC ISO datetimes).
   - `errors.py`: RFC 9457 `ProblemDetail`, `FieldErrorDetail`, and `ErrorCode` enum registry.
   - `metadata.py`: `ResponseMetadata` carrying `request_id`, UTC timestamp, and version.
   - `pagination.py`: `PaginationParams`, `PageInfo`, `PaginatedResponse[T]`.
   - `filtering.py`: `FilterOperator`, `FilterCondition`, `SortOrder`, `SortParams`.
   - `identifiers.py`: Validated slug, UUID, and schema object identifier validators.
2. **Centralized Exception Handling Upgrade (`apps/api/src/dera_api/core/exceptions.py`):**
   - Integrate domain exception hierarchy (`DeraError`, `ValidationDomainError`, `ResourceNotFoundError`, `ConflictError`, `DependencyUnavailableError`).
   - Emit RFC 9457 `application/problem+json` responses for all errors with preserved `request_id`.
   - Normalize Pydantic validation errors safely without reflecting sensitive user values.
3. **OpenAPI Specification Governance & Snapshot Testing:**
   - Export authoritative OpenAPI v1 document to `docs/api/openapi.v1.json`.
   - Implement `scripts/ci/validate_openapi.py` to enforce zero unauthorized contract drift in CI.
   - Add contract regression tests in `tests/contracts/`.
4. **Documentation Deliverables (`docs/api/`):**
   - Authoritative API contract standard, error model, validation policy, pagination, and versioning documents.
5. **Quality Verification & Acceptance:**
   - Execute full validation suite (`dev.py all`), update acceptance report, and open reviewable pull request.
