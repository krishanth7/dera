# DERA Diagnostics — Evidence Model

**Milestone:** Phase 8.1 — Deterministic Schema Diagnostic Rules Engine  
**Module:** `packages/core/src/dera/diagnostics/evidence.py`  
**Status:** Canonical Reference  

---

## 1. Specification

Findings generated by DERA rules must be grounded in discrete, verifiable evidence items.

```python
@dataclass(frozen=True)
class DiagnosticEvidence:
    object_id: str
    field_name: str
    observed_value: Any
    expected_value: Any | None = None
    message: str = ""
    provenance_reference: str | None = None
    context_data: dict[str, Any] = field(default_factory=dict)
```

---

## 2. Evidence Minimization & Sanitization

To ensure data protection and zero leakage of customer credentials:
1. **Password Redaction:** URI connection strings matching `://<user>:<pass>@` are automatically redacted to `://***:***@`.
2. **Key Filtering:** Context keys matching sensitive patterns (`password`, `secret`, `token`, `api_key`, `credential`) are masked as `[REDACTED]`.
3. **No Row Data:** Rules inspect structural metadata only; customer row records are never queried or embedded in evidence.
