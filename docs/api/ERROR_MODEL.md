# DERA Error Model & RFC 9457 Problem Details

All error responses in DERA comply with [RFC 9457 (Problem Details for HTTP APIs)](https://datatracker.ietf.org/doc/html/rfc9457) and use the standard media type:

```http
Content-Type: application/problem+json
```

---

## 1. Problem Details Schema

An RFC 9457 Problem Details response contains standard top-level attributes extended with machine-readable DERA diagnostics:

```json
{
  "type": "https://api.dera.io/v1/errors/VALIDATION_ERROR",
  "title": "Validation Failed",
  "status": 422,
  "detail": "The request contains invalid or unprocessable parameters.",
  "instance": "/api/v1/schemas",
  "code": "VALIDATION_ERROR",
  "request_id": "req-c83f124a-7182-41f2-938b-1188234abcf9",
  "errors": [
    {
      "field": "page_size",
      "code": "VALUE_TOO_LARGE",
      "message": "Input should be less than or equal to 100",
      "constraint": "le=100"
    }
  ],
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request contains invalid or unprocessable parameters.",
    "request_id": "req-c83f124a-7182-41f2-938b-1188234abcf9",
    "details": []
  }
}
```

### Core Field Definitions

* **`type`** (string): Absolute URI dereferencing the specific error category documentation.
* **`title`** (string): Short, human-readable summary of the problem type (does not change between occurrences).
* **`status`** (integer): The HTTP status code generated by the origin server.
* **`detail`** (string): Human-readable explanation specific to this occurrence.
* **`instance`** (string, optional): The request URI path where the error occurred.
* **`code`** (string): Authoritative machine-readable classification enum from `ErrorCode`.
* **`request_id`** (string, optional): Correlation identifier for request tracing and log alignment.
* **`errors`** (array, optional): Detailed list of field-level validation errors (for 422 responses).
* **`error`** (object, optional): Backward-compatible envelope providing seamless compatibility with Phase 4.1 clients.

## 2. Authoritative Error Code Taxonomy

| Error Code | HTTP Status | Meaning | Retryable | Client Remediation |
|---|---|---|---|---|
| **`VALIDATION_ERROR`** | `422` | Request body or query params failed schema constraints | No | Correct invalid fields according to the `errors` array |
| **`MALFORMED_REQUEST`** | `400` | Unparseable JSON or invalid request syntax | No | Ensure payload is valid RFC 8259 JSON |
| **`UNSUPPORTED_MEDIA_TYPE`** | `415` | Request `Content-Type` is not `application/json` | No | Set `Content-Type: application/json` |
| **`RESOURCE_NOT_FOUND`** | `404` | Requested path or database entity was not found | No | Verify entity ID or path spelling |
| **`METHOD_NOT_ALLOWED`** | `405` | HTTP verb is not supported for this endpoint | No | Consult OpenAPI docs for supported verbs |
| **`CONFLICT`** | `409` | State conflict (e.g. unique constraint or concurrency) | Conditional | Inspect current resource state and retry |
| **`RATE_LIMITED`** | `429` | Request rate limit exceeded | Yes | Back off and retry after delay |
| **`INTERNAL_ERROR`** | `500` | Unexpected server fault or bug | Conditional | Contact support or retry with exponential backoff |
| **`SERVICE_UNAVAILABLE`** | `503` | API Gateway is shutting down or in maintenance | Yes | Retry with exponential backoff |
| **`DEPENDENCY_UNAVAILABLE`** | `503` | Target database engine or pool is unresponsive | Yes | Retry with exponential backoff |

## 3. Information Leak Prevention & Security

1. **Traceback Scrubbing**: Unhandled exceptions (`500`) are logged server-side with complete stack traces, but client responses receive only:
   ```json
   {
     "type": "about:blank",
     "title": "Internal Server Error",
     "status": 500,
     "detail": "An unexpected error occurred while processing the request.",
     "code": "INTERNAL_ERROR",
     "request_id": "req-..."
   }
   ```
2. **Secret Masking**: Database credentials, passwords, session tokens, and connection strings are strictly stripped from all error messages.
3. **No Sensitive Input Reflection**: Validation errors output field locations and failure constraints (`STRING_TOO_SHORT`, `VALUE_TOO_LARGE`) without echoing back sensitive user input values.
