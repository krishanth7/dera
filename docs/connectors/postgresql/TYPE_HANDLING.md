# PostgreSQL Type Handling Guide

## Type Preservation Strategy

The PostgreSQL connector utilizes `format_type(a.atttypid, a.atttypmod)` to retrieve accurate, canonical native type declarations rather than simplifying data types to generic strings.

### Built-in Scalar Types
- Integers: `smallint`, `integer`, `bigint`.
- Floating-point: `real`, `double precision`, `numeric(precision, scale)`.
- Characters: `character varying(n)`, `character(n)`, `text`.
- Binary: `bytea`.
- Boolean: `boolean`.
- Temporal: `timestamp without time zone`, `timestamp with time zone` (`timestamptz`), `date`, `time without time zone`, `time with time zone`, `interval`.
- UUID: `uuid`.
- Network: `inet`, `cidr`, `macaddr`.

### Structured & Extended Types
- **JSON & JSONB:** Preserved with native names `json` and `jsonb`.
- **Arrays:** Preserved with bracket notation (e.g. `text[]`, `integer[]`, `uuid[]`).
- **Enums & Domains:** Preserved using user-defined type identifiers.
- **Identity & Auto-Increment:** Captured via `is_identity` (`a.attidentity != ''`) reflecting standard SQL `GENERATED ALWAYS AS IDENTITY` or `GENERATED BY DEFAULT AS IDENTITY`.
- **Generated Columns:** Captured via `is_generated` (`a.attgenerated != ''`) and `generation_expression` reflecting stored generated columns.
- **Collations:** Explicit non-default collations captured in `engine_specific['collation']`.
